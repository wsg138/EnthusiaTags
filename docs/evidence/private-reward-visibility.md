# Optional private reward visibility — SPEAR draft

Source baseline: a2fdecaa05ac726efd010b34406d711beffb16f8. No particular event, tag name, reward or recording is added by this change.

A private reward's `hidden-until-earned: true` filters it before reward rows, counts and public advancement projection. Direct focused opens and stale claim clicks are denied until durable unlock/claim state is loaded. Unlock notifications for private rewards are suppressed here; a separately authorized producer owns any private celebration. A tag linked using `hidden-until-reward: <reward-id>` is omitted from unearned preview/catalog and cached placeholders; unavailable state and invalid references fail closed. These opt-ins preserve existing public behavior and old constructors. Malformed explicit reward flags and blank tag references fail closed.

**Configuration boundary:** both the reward flag and tag reference must be present and match. No user-specific private configuration is included. A missing tag marker on a configured secret tag cannot be inferred while the reward service is unavailable; a missing reward flag can expose its card. Treat validating the exact paired configuration and all references as a release gate, not as an implemented guarantee against every administrator misconfiguration. Staff-only diagnostics and administrative operations remain privileged. The originating provider must record completion durably and idempotently; this change does not create or award it.
